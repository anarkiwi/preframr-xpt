# Digi techniques and detection — grounded in C=Hacking #20 + Mahoney's white paper

**Status:** Reference (2026-06-03). Sources: C=Hacking #20, "The C64 Digi" (Harbron/Harsfalvi/Judd),
http://www.ffd2.com/fridge/chacking/c=hacking20.txt; and "Technical details of Musik Run/Stop" (Pex
'Mahoney' Tufvesson, 2014), https://livet.se/mahoney. Written to refine `dump_meta.is_digi`, which
misses PWM digis, and to correct a process error of mine (excluding a non-digi tune by row count — see
the Baggis note below).

## The two real digi playback methods (and their register signatures)

SID plays only one digi at a time; "samples" are a series of average output-voltage values produced
one of two ways:

### 1. $D418 volume-register digi (by far the most common)
- **Per-sample write:** the 4-bit volume nibble at **$D418** (tokenizer `MODE_VOL`, reg 24). One write
  per sample; sample rate = write rate (often many writes per frame / sub-frame).
- **8580 "boost" setup (one-time, not per-sample):** because the 8580 lacks the 6581 residual voltage,
  a carrier is generated by configuring a voice as **pulse + TEST bit** with **sustain = $F**:
  `STA $D406 (=$FF sustain)`, `STA $D404 (=$49 = gate|test|pulse)`. This ctrl/SR setup happens ONCE;
  the per-sample modulation stays on $D418.
- **Log signature:** high **MODE_VOL writes/frame**. (The boost adds a *one-time* pulse+test ctrl
  config — NOT per-sample ctrl writes.)

### 2. Pulse-Width-Modulation (PWM) digi
- Get past the 4-bit limit: configure a voice with a **pulse waveform at frequency ≈ 0** and the
  **TEST bit set** (PRG: TEST "holds the Pulse waveform output at a DC level"), then **modulate the
  pulse-width register $D402/$D403** to set each pulse's duty cycle = sample value (e.g. toggle $D403
  between $00/$FF, or set width = sample). Quote: "set up a pulse waveform at zero frequency and use
  the pulse width registers to toggle the voltage -- set $d403 to either $00 or $ff." Can reach ~16 kHz
  (sub-frame, the modulation loop is in machine cycles).
- **One-time setup:** ctrl = pulse+test ($D404), sustain = $F ($D406), freq = 0. **Per-sample writes go
  to PULSE WIDTH** ($D402/$D403; tokenizer `PW_LO`/`PW_HI`, regs `v*7+2`/`v*7+3`).
- **Log signature:** high **PW writes/frame** on a voice configured pulse+test+freq0 — with **low**
  $D418 and **low** ctrl write density.

(Control-register bits, $D404: gate = bit0 0x01, test = bit3 0x08, pulse = bit6 0x40; `$49` =
gate|test|pulse.)

### 3. Mahoney 8-bit $D418 digi (Musik Run/Stop, 2014)
A refinement of the $D418 method that gets ~8-bit, ~44 kHz from the 4-bit volume register by exploiting
combined-voice DC offsets + the filter's ≈ −1 gain. **One-time setup on all three voices:** AD = $0F
($D405/$D40C/$D413), SR = $FF ($D406/$D40D/$D414), **ctrl = $49 (pulse + TEST + gate)**
($D404/$D40B/$D412), filter cutoff = $FF ($D415/$D416), `$D417 = $03` (voices 1+2 routed through
filter; no HP/BP/LP so the muxes also pass unfiltered). **Per-sample: a single write to $D418** indexed
through a precomputed non-linear 256-entry amplitude table, every ~21 CPU cycles (~900 writes/PAL
frame). **Log signature:** extreme $D418 write density (hundreds/frame) PLUS the all-3-voice
test+pulse+sustain=$F+filter setup. Caught by `vol_max` (it's huge), but the setup fingerprint is what
distinguishes 8-bit Mahoney from a plain 4-bit $D418 digi.

### 4. SounDemoN test-bit sample-and-hold (2008)
One voice, TEST bit + triangle, "sample-and-hold by briefly enabling the waveform." **~4 writes per
sample** (incl. per-sample CONTROL writes to toggle the waveform enable), 8–16 kHz. **Log signature:
dense CONTROL writes/frame** on a test-bit voice — so a ctrl-dense *digi* does exist. This is the one
case where `ctrl_max` is a legitimate digi signal (at 16 kHz ≈ 320 ctrl writes/frame, far above any
music driver).

## What this means for detection
`dump_meta.is_digi = (vol_max >= 40 or ctrl_max >= 20)` where `vol_max`/`ctrl_max` = max writes/frame to
$D418 / voice-ctrl regs. Mapping each method to a signature:
- **`vol_max >= 40`** correctly catches $D418 digis (4-bit AND Mahoney 8-bit — Mahoney is hundreds of
  $D418 writes/frame).
- **`ctrl_max >= 20`** is **defensible** — it catches the SounDemoN test-bit sample-and-hold digi
  (per-sample ctrl/waveform toggling; ≈320 ctrl writes/frame at 16 kHz). 20/frame is well above any
  music driver (the melodic tunes measured here peak at **ctrl_max = 3**), so the threshold is not the
  problem. (My earlier claim that this was a false-positive generator was wrong — SounDemoN makes it a
  real signal.)
- **PWM digis are MISSED** — the real gap. The heuristic never checks PW ($D402/$D403) write density, so
  a PWM digi (low vol, low/normal ctrl, **high PW**, voice configured pulse+test+freq≈0) is invisible.

## Refined detection (proposal)
Add the missing PWM signature; keep the others:
- **$D418 / Mahoney:** `vol_writes_per_frame_max >= T_vol` (Mahoney optionally distinguished by the
  all-3-voice ctrl=$49 + sustain=$FF + filter setup).
- **SounDemoN:** `ctrl_writes_per_frame_max >= T_ctrl` (keep).
- **PWM (ADD):** `pw_writes_per_frame_max >= T_pw` on a pulse+test+freq≈0 voice (or high PW density as a
  cheap proxy).
- Row count / total writes is **NOT** a digi signal — it just means a long/multispeed tune. Use the
  per-frame write-density signatures above, never raw length.

## Baggis — process error, corrected
I excluded `Goto80/Baggis.1` from the residual read as a "digi" because it had 5× the rows (98k vs ~20k).
That was wrong on two levels: (1) the `is_digi` heuristic **does not flag it** — measured `vol_max=1`,
`ctrl_max=3`, `pw_max=6`, zero test+pulse configs ⇒ `is_digi=False`; (2) row count isn't a digi signal.
Baggis is just a long (13,229-frame), ctrl-active **non-digi** tune (consistent with defMON, which has
no PCM digi). Excluding it discarded the most informative case: its CTRL residual (~4000 raw-SET ctrl
writes) includes **788 multi-frame consecutive-frame runs (up to length 12)** that `ctrl_bigram`/
`ctrl_triple` (2-/3-frame only) don't collapse — a real, patterned, **compressible** opportunity, not an
"irreducible floor." (Melodic tunes differ: Camerock's 76 residual ctrl writes are all isolated
single-frame transitions — low compressibility. So the ctrl-residual opportunity is concentrated in
ctrl-active drivers.) Lesson logged: stop labeling things "irreducible floors" before measuring.
