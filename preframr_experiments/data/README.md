# Pinned data tiers

Stable HVSC corpus lists consumed by ``preframr_experiments``. With the BACC
codec the corpus is selected **sid-only**: each entry is a ``.sid`` recovered
directly through the codec (no pre-rendered ``.dump.parquet``).

Entry format, one per line (trailing ``# ...`` comments stripped at parse):

```
<C64Music-relative .sid path><TAB><1-based subtune>
```

Resolved against the HVSC root (``run.py --src-root``, default
``/scratch/preframr/hvsc/C64Music``). The runner stages each entry's ``.sid``,
emits a manifest, and the framework parser recovers it sid-only.

## How the corpus is selected

Selection is driven by a **codec-coverage census**, not by hand-picked composers.
Two ground-truth axes the codec now exposes:

1. **Tracker** — `/scratch/anarkiwi/cbm/hvsc-tracker-catalog/data/results.csv`
   maps every ``.sid`` to its player/tracker (SIDId).
2. **Encodability** — whether the codec recovers the tune **residual-zero**
   (byte-exact) and the whole-song **token count**.

The pipeline (`preframr_experiments/corpus/`):

- `census.py` — runs `recover_from_sid` over the full HVSC × subtune, recording
  `residual_ok`, `n_tokens`, `n_frames`, tracker, driver → `census.parquet`
  (resumable sharded). The single source of truth for selection.
- `select.py` — from the census, **gates on `residual_ok`**, requires
  **`n_tokens <= 4096`** (whole-song-in-context), **stratifies by tracker**
  (capped per composer), holds out eval splits, and writes the tier `.list`
  files + each tier's `HVSC_VERSION`. `--report` prints the % of the corpus
  ≤ 4096 tokens per tracker.
- `hvsc.py` — Songlengths frame budgets + the tracker-catalog loader.

## Tiers

All membership is residual-zero and ≤ 4096 tokens (one context window), sized in
whole songs.

- `smoke.list` — one gate fixture per backend family (Hubbard, GoatTracker, lft,
  DMC); end-to-end pipeline smoke. Hand-pinned (mirrors `select.SMOKE_FIXTURES`).
- `mini/` — small tracker-balanced set for fast arm decisions.
- `canonical/` — primary A/B: medium multi-tracker train + in-distribution
  (`eval-A`) and held-out-composer (`eval-B-<composer>`) splits.
- `frontier/` — the full whole-song-in-context corpus (every residual-zero tune
  ≤ 4096 tokens), with the canonical eval holdouts. The > 4096 tail is excluded
  (an opt-in windowed variant, never truncated).

Each tier dir carries `train.list`, `eval-A.list`, `eval-B-*.list`, and a pinned
`HVSC_VERSION`. `mini/`, `canonical/`, and `frontier/` are **generated by
`select.py`** (committed when re-pinned); they are absent until the census runs.

## Re-pin procedure

Re-curation is a deliberate, commit-logged event.

```bash
# 1. Census the full HVSC (resumable; run on a many-core box).
PYTHONPATH=. python3 -m preframr_experiments.corpus.census \
    --hvsc /scratch/preframr/hvsc/C64Music \
    --catalog /scratch/anarkiwi/cbm/hvsc-tracker-catalog/data/results.csv \
    --songlengths /scratch/preframr/hvsc/C64Music/DOCUMENTS/Songlengths.md5 \
    --tokens-src /scratch/anarkiwi/preframr/preframr-tokens \
    --out /scratch/preframr/census --workers 20

# 2. Inspect coverage (residual-zero rate + % <= 4096 per tracker).
PYTHONPATH=. python3 -m preframr_experiments.corpus.select \
    --census /scratch/preframr/census/census.parquet --report

# 3. Pin the tiers (writes data/<tier>/{train,eval-A,eval-B-*}.list).
PYTHONPATH=. python3 -m preframr_experiments.corpus.select \
    --census /scratch/preframr/census/census.parquet \
    --heldout-composer <Composer> ...
```

`smoke.list` is hand-edited (record the rationale in the commit message).

## Why pin?

Pre-pin, selection drifted as the corpus mirror moved, breaking arm-level
comparability across runs. Post-pin, every arm of every experiment runs on
identical paths until a re-pin commit explicitly changes them, and the census
makes the selection reproducible from a single source of truth.
